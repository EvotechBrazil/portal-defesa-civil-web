NOTA DE HANDOFF · IMPLEMENTAÇÃO Mesclar reaponta as FKs de User e AccessRequest para a manada vencedora e descarta a perdedora. Precisa ser transação única — metade das FKs movidas é pior que nenhuma — e precisa registrar qual virou qual (id perdedora, id vencedora, autor, timestamp, contagem movida). Sem esse registro, um merge errado não tem como ser reconstruído. O desenho cobre a parte dele: confirmação com nome das duas manadas, quantas pessoas se movem, total resultante, aviso explícito de irreversibilidade e checkbox de ciência. O botão só habilita com o checkbox marcado.
Mesclar existe porque duplicata vai passar: move as pessoas da manada nova para a existente e apaga a duplicada, sem quebrar histórico de estudo. Sem essa ação, verificar seria uma escolha entre aprovar sujeira ou recusar gente de boa-fé.
Comportamento do combobox: foco no campo → abre a lista com o filtro automático já aplicado → digitar filtra dentro de todos os degraus (não só do primeiro) → ↑↓ navega, Enter escolhe, Esc fecha e devolve o foco ao gatilho. role="combobox" + aria-expanded + aria-activedescendant; o grupo de cada degrau é um role="group" com rótulo, então o leitor de tela anuncia “mesma cidade, 2 itens”. Selo de verificação é ícone + texto, nunca só cor. Sem dependência nova: datalist não permite os grupos nem os selos, então o combobox é markup próprio com input + lista — CSS puro, sem lib.

Notas dos grupos B e C

  • Dívida 4 endereçada: 452 linhas com 4 passos e 8 campos → gate de 1 campo + 3 blocos de 2–3 campos + foto opcional fora do caminho crítico. Nenhum bloco tem mais de uma decisão real.

  • Interações: gate → máscara aplicada a cada tecla → retorno em ≤2s com um dos 4 estados → botão do estado. Recorte de foto → arraste ou setas do teclado, zoom por slider com aria-valuetext. Tour → toque/Enter na carta demo → flip → botões de avaliação ganham foco. Cooldown → contagem em texto, botão desabilitado com aria-live.
